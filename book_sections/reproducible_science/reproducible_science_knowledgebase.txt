## CHAPTER: Reproducible Science

### Chapter-Wide Learning Goals

By the end of this chapter, students should be able to:

1. Describe best practices for collecting, labeling, storing, and documenting data.
2. Design tidy, consistent data sheets for field or lab collection.
3. Understand the role of a README and data dictionary.
4. Create a logical folder structure and initiate an R Project for reproducible analysis.
5. Load data into R using relative paths.
6. Write reproducible R scripts with informative comments.
7. Clean and tidy data in R.
8. Apply best practices for organizing and documenting analyses.

---

## Background Context for Students

* Students have not necessarily conducted fieldwork or coded reproducibly before.
* They have some exposure to reading and writing R scripts.
* They may confuse absolute vs. relative paths.
* They may not know how to structure folders or create projects.
* They are encouraged to reflect on real-world scientific practices (lab notebooks, naming files, data storage).
* They should begin thinking of themselves as future researchers.
* They may believe “it ran once” means code works reproducibly.

---

## Core Definition to Reinforce

**Reproducibility:** Someone else (or future you) can run your code on the same data and obtain the same results.

---

## Key Concepts to Reinforce

* Start reproducibility at the beginning of a project.
* Use consistent naming and data entry practices.
* Always save raw data; never overwrite it.
* Store data and scripts together in a logical structure.
* R Projects make relative paths reliable.
* Every data transformation should happen in a script.
* Scripts should run top-to-bottom in a fresh session.
* Scripts should begin with author, date, and purpose.
* Avoid using formatting (bold, color) as data.
* Reproducible code benefits both science and future you.

---

## AmNat Reproducibility Guidelines (Instructor Emphasis)

The chapter draws on **The American Naturalist** reproducibility policy. Students should understand these principles:

### REQUIRED

* Scripts begin by loading packages and importing raw data.
* Use relative paths (avoid `setwd()`).
* Code must run in a fresh session.
* Comment code to explain purpose (“why”).
* Link code to figures/tables in the manuscript.
* Cite packages and reused code.

### RECOMMENDED

* Test code on a clean machine or new session.
* Use informative names for files and variables.
* Perform all data manipulation in scripts.
* Organize code into logical sections.
* Label sections to match figures/tables.
* Remove unused code or move to a coda.

Students are **not expected to memorize** these but should recognize their purpose.

## Awareness of Embedded Quiz Items

Tutor should guide thinking without giving answers.

Common quiz themes:

* tidy vs untidy data
* relative vs absolute paths
* README vs data dictionary
* reproducible scripts
* raw data preservation

---

## Common Student Misconceptions

Tutor should watch for:

* “If it runs once, it works.”
* Confusing spreadsheet formatting with data.
* Believing raw data can be edited safely.
* Thinking folder structure is optional.
* Treating interactive console steps as reproducible.

---

## Tutoring Tone and Tactics

* Emphasize real-world relevance (“future you will thank you”).
* Ask students to describe their current workflow.
* Encourage planning before coding.
* Keep code examples minimal unless requested.
* Praise investment in organization and clarity.
